# סידור משמרות לבית קפה

> **עותק ציבורי להצגה.** המערכת עצמה רצה מאז אוקטובר 2026 בבית הקפה פטלינה, עם כל הצוות,
> ממאגר פרטי. כאן הקוד בגרסה עדכנית, בלי היסטוריית הפיתוח: השמות בנתוני הדוגמה ובבדיקות בדויים,
> ותמונת הגיליון המקורי הוסרה כי יש בה שמות אמיתיים.

אפליקציית ווב לניהול סידור העבודה השבועי: העובדים מגישים זמינות מובנית עד מועד
אחרון, ואחריו נבנית טיוטת סידור אוטומטית שהמנהל מתקן ומפרסם — בפריסה זהה לגיליון
שאיתו עבדתם עד היום.

## האפליקציה החיה

**פרוסה על Vercel**, פונקציות ב-`fra1` (פרנקפורט), עם Prisma Postgres **באותו
אזור**. הפריסה אוטומטית מכל דחיפה ל-`main`.

> **האפליקציה והמסד חייבים לשבת באותו אזור.** בפריסה הראשונה (על Prisma
> Compute) האפליקציה נחתה בניוארק בעוד המסד בפרנקפורט, וכל שאילתה חצתה את
> האוקיינוס — דפים לקחו 500-700ms במקום 200. האזור נקבע ב-`vercel.json`.

```bash
git push                             # זו הפריסה
npx prisma migrate deploy            # מיגרציות — בנפרד, וידנית
```

**מיגרציות אינן חלק מהבנייה בכוונה.** הן היו רצות בכל פריסה, כולל preview,
ומשנות סכימה בלי שאיש הסתכל.

`prisma generate` **כן** חלק מהבנייה: Vercel שומר את התלויות במטמון בין
פריסות, ולכן `postinstall` לא תמיד רץ — והלקוח נשאר ישן אחרי שינוי סכימה.
זו התקלה הידועה של Prisma על Vercel.

## הרצה מקומית

```bash
npm install
npx prisma migrate deploy
npm run db:seed
npm run dev
```

`.env` מצביע על אותו Postgres בענן, כך שפיתוח מקומי ופרודקשן חולקים מסד נתונים.
לפני שהצוות מתחיל לעבוד באמת — כדאי להקים מסד נפרד לפיתוח
(`npx @prisma/cli@latest database create shifts-dev --region eu-central-1`).

- כניסה אחת לכולם: `/login` — טלפון + קוד אישי
- מי שיש לו `canManage` רואה גם את `/manager`; כל השאר רואים רק את `/me`

## איך נכנסים

**טלפון + קוד בן 6 ספרות.** אין SMS ואין אימייל: המנהל מייצר קוד במסך
**עובדים**, שולח אותו בוואטסאפ, והעובד בוחר קוד משלו בכניסה הראשונה.

| | |
|---|---|
| שם משתמש | הטלפון, מנורמל ל-`972…` (`src/lib/phone.ts`) |
| סיסמה | 6 ספרות, נשמרות כ-scrypt בלבד (`src/lib/passcode.ts`) |
| סשן | עוגייה חתומה ב-HMAC שנושאת `employeeId`, 30 יום |
| הגבלת קצב | 5 כישלונות → נעילה של 15 דקות (`src/lib/lockout.ts`) |

**הקוד מוצג פעם אחת בלבד.** הוא לא נשמר בשום מקום — רק הגיבוב שלו. מי שסגר
את החלון בלי להעתיק מייצר קוד חדש. אותו דבר לגבי עובד ששכח: **איפוס קוד**
בשורת העובד.

ההרשאה ו-`active` **נקראים מהמסד בכל בקשה** ולא מהעוגייה, ולכן שלילת הרשאת
ניהול או הוצאת עובד תופסות מיד ולא בעוד 30 יום.

> **הסשן אינו הקישור.** קישור עבד בכל דפדפן; סשן לא. מי שפותח את ההודעה
> בוואטסאפ נכנס בדפדפן הפנימי שלו, והסשן יישאר שם. לכן העוגייה ל-30 יום,
> ולכן מסך הכניסה ממליץ לפתוח בדפדפן רגיל.

### דלת החירום

אין `MANAGER_PASSWORD` יותר. אם חשבון המנהל האחרון ננעל או נמחק, הדרך חזרה
היא `npm run access` מהמחשב — הוא רץ מול המסד ישירות:

```
npm run access list                              מי מנהל ומה מצב הכניסה שלו
npm run access bootstrap "שם מלא" 050-1234567    חשבון ניהול חדש
npm run access grant  050-1234567                הרשאת ניהול לעובד קיים
npm run access reset  050-1234567                קוד כניסה חדש
```

הממשק עצמו מסרב להסיר את הרשאת הניהול האחרונה ולהוציא את המנהל האחרון, כדי
שלא תהיה דרך לנעול את כולם בחוץ בלחיצה.

### גיבוי ההגשות

מה שאי אפשר לייצר מחדש הוא מה שהעובדים סימנו. סידור אפשר לבנות שוב בלחיצה,
אבל הגשה שנמחקה נעלמה — ו-`Availability` ו-`Submission` תלויים בשבוע
ב-`Cascade`, כלומר **מחיקת שבוע מוחקת את כל ההגשות שבו**. (בנייה מחדש של
הסידור, לעומת זאת, נוגעת רק ב-`Assignment` שאינם נעוצים.)

```
npm run week:backup                             השבוע הפתוח → backups/…json
npm run week:backup -- --week 2026-08-23        שבוע לפי תאריך התחלה
npm run week:restore -- backups/x.json          הרצה יבשה
npm run week:restore -- backups/x.json --apply  החלה
```

הגיבוי הוא קריאה בלבד ובטוח להריץ מול הייצור בכל רגע. הקובץ שומר **מפתחות
טבעיים** ולא מזהים — עובד לפי טלפון, משבצת לפי יום·תפקיד·שעות·סדר — כי
`WeekSlot` נוצר מחדש עם `cuid` חדש בכל פתיחת שבוע, וגיבוי ששומר מזהים היה
חסר ערך בדיוק בתרחיש שבשבילו הוא נבנה. השחזור עובד `upsert` ולכן אינו
משכפל, ומדווח בשמם על עובדים או משבצות שלא נמצאו במקום לבלוע אותם.

`/backups` ב-gitignore: הקובץ מכיל שמות וטלפונים אמיתיים.

`npm run test:roundtrip` מוחק שבוע ובונה אותו מחדש כדי להוכיח שהמפתחות
הטבעיים באמת עובדים אחרי שהמזהים מתחלפים — ולכן הוא מסרב לרוץ מול
`DATABASE_URL`, כמו `db:seed` ו-`test:e2e`.

## איך זה עובד

### התבנית השבועית

נזרעה מהגיליון: ימים א׳–ה׳ עם 16 משבצות (אחמ״ש בוקר, 3 ברמנים, 6 מלצרי בוקר,
אחראי ערב, 5 מלצרי ערב), שישי במבנה נפרד של 13 משבצות עם שעות עלייה מדורגות,
ושבת סגורה. הכל ניתן לעריכה במסך **תבנית שבועית**.

פתיחת שבוע מעתיקה את התבנית לעותק משלו, כך שעריכת התבנית לא שוברת הגשות של שבוע
שכבר נפתח.

> **לבדוק לפני השימוש הראשון:** שעות האחמ״שים ושעות הסיום של מלצרי שישי לא הופיעו
> בגיליון ולכן נזרעו בהערכה.

### הגשת זמינות — שעות קודם

עובד לא חושב "משבצת 08:15–15:00". הוא חושב **"ביום שלישי אני פנוי מ-9 עד 2"**.
לכן זו נקודת הפתיחה של הטופס:

1. **"מתי אתה פנוי ביום הזה?"** — שתי שעות, מ־ ועד. אפשר להשאיר ריק.
2. **המערכת מסמנת אוטומטית** כל משבצת שנכנסת בחלון, ומציגה על כל אחת מה בפועל
   ייצא ממנה: *"תעבוד 09:00–14:00 (5 שעות)"*.
3. **כיוונון ידני** — לחיצה על משבצת מחליפה בין ✕ לא יכול ← ✓ יכול ← ★ מעדיף.
   למי שאין אילוצים יש קיצורי "כל הבוקר" / "כל הערב".

החלון נשמר לכל יום בנפרד ומוחל על כל המשבצות שסומנו בו.

**כללי הגמישות** (`fitSlot` ב-`src/lib/time.ts`) אינם סימטריים, כי המשמרת בבית
קפה אינה סימטרית:

| כלל | מי | למה |
|---|---|---|
| **פתיחה** — חובה להגיע בשעה המדויקת | המשבצת הראשונה בכל סבב | אחרת אין מי שיתחיל את המשמרת |
| **סגירה** — חובה להישאר עד הסוף | שתי המשבצות האחרונות בכל סבב | אחרת אין מי שיסגור |
| **מינימום 4 שעות** | כל שיבוץ חלקי | מתחת לזה לא שווה לשבץ |
| **אין מעבר בין סבבים** | מלצרים בלבד | ברמן צהריים ואחראי ערב מגשרים במכוון |

בשאר המשבצות מותר להגיע מאוחר וגם לרדת מוקדם. הדגלים `fixedStart` / `fixedEnd`
נשמרים על כל משבצת וניתנים להחלפה בלחיצה במסך התבנית.

### כיסוי חלקי — החלטה של המנהל

**האלגוריתם משבץ אך ורק מי שמתאים למשמרת המלאה.** אין אף מסלול שבו הוא בוחר
כיסוי חלקי בעצמו: `buildCandidateIndex` מפריד את המועמדים ל-`bySlot` (מלאים,
היחיד שהפותר קורא ממנו) ו-`partialBySlot` (חלקיים, לתצוגה בלבד).

כשאין אף מתאים, **המשבצת נשארת ריקה** והתא בטבלה מציג `2 אפשרויות`. לחיצה
פותחת בורר בארבע קבוצות לפי סדר השימושיות:

| קבוצה | מי |
|---|---|
| מתאימים למשמרת המלאה | סימנו והשעות מתאימות |
| מכסים חלק מהמשמרת | סימנו, עם *"יכסה 09:45–16:00 · 6.25 מתוך 6.75 שעות"*, ממוין לפי כמה שהם מכסים |
| לא סימנו את המשמרת | מקופל — אפשר לשבץ בכל זאת |
| לא זמינים | מקופל, עם הסיבה לכל אחד |

בחירה ידנית נשמרת עם השעות בפועל, ננעצת, ומסומנת מאושרת — אין תור אישורים
נפרד. הפרסום אינו נחסם: ייתכן שאין למנהל ברירה, והוא רואה את המצב בכרטיס
האזהרה.

### רצפת האיוש

ברגע שמותר לרדת מוקדם, אף שיבוץ בודד לא נראה בעייתי — אבל הצירוף שלהם כן, ואפשר
להגיע ליום שבו כולם יורדים ב-14:00. `src/lib/coverage.ts` אוכף רצפה:

```
רצפה(t) = min(כמה מלצרים התבנית מתכננת ב-t, 4)
```

ה-`min` מטפל בעליית הבוקר (ב-07:15 מתוכנן מלצר אחד, אז הרצפה 1) ובזנב הלילה
(ב-22:15 נשארים שניים) בלי מקרי קצה. הרצפה נספרת על פני **כל היום יחד**, כי בין
16:00 ל-17:00 מלצרי שני הסבבים ברצפה במקביל.

האלגוריתם מעניש חוסר איוש ב-25 נקודות לדקה לאיש — יקר יותר משיבוץ חלקי וזול
יותר ממשבצת ריקה — כך שהוא מחליף יורדי-מוקדם בנשארים, אבל לא משאיר תא ריק כדי
לשמור על הרצפה. מה שנשאר מופיע ככרטיס אזהרה אדום במסך השבוע עם השעות המדויקות,
ואינו חוסם פרסום.

> `MIN_SHIFT_MINUTES` משותף לטופס ולאלגוריתם. אם הם יתפצלו, סימון שהעובד הגיש
> ייעלם בשקט בשלב השיבוץ.

### פרופיל העובד

`requiredShifts`, `maxShifts`, `canClose`, ותק והערות פנימיות — **גלויים למנהל
בלבד**. מסכי העובד שולפים רק שם ותפקידים ולא נוגעים בשדות האלה.

**ותק (1-5)** מפזר ניסיון בין המשמרות: העלות מענישה את השונות של ממוצע הותק
בין משמרות המלצרים (יום + סבב), כך שלא ייווצר יום שכולו ותיקים לצד יום שכולו
חדשים. משמרת מעורבת כמו [5,5,1,1] מקבלת אותו ממוצע כמו [3,3,3,3] ואינה נענשת —
וזה נכון, הוותיקים אכן פזורים בה.

חל על **מלצרים בלבד**: אחמ"שים וברמנים הם 1-3 במשמרת ובדרך כלל אותם אנשים.

> המשקל נבחר לפי מדידה, לא הערכה. סריקה מ-150 עד 10,000 נתנה תוצאה זהה —
> האילוצים הקשיחים תוחמים ממילא את מרחב הפתרונות, והמשקל פועל כשובר-שוויון
> בלבד. השיפור בפועל: שונות 0.095 → 0.080, בלי לפגוע באחוז האיוש (75) או
> במספר השיבוצים ל"מעדיף" (32).

### האלגוריתם

`src/lib/scheduler/` — TypeScript ללא תלויות, ~90 משבצות נפתרות בעשרות מילישניות.

**אילוצים קשיחים:** תפקיד תואם · סומן זמין · חלון הזמינות מתאים · הרשאת סגירה
למשבצות סגירה · משמרת אחת ליום · אין הפרת "לא עובדים יחד" · מקסימום משמרות ·
8 שעות מנוחה בין משמרות.

**מה הוא ממטב, מהכבד לקל:** משבצות ריקות (אחמ״ש חמור מכולם) → פערים מול מכסת
המשמרות → שיבוץ ל"יכול" במקום "מעדיף" → משמרות מקוצרות → איזון משמרות הסגירה.

**חיפוש:** בנייה חמדנית לפי נדירות, ואז חיפוש מקומי עם מהלכי move / swap /
transfer. `seed` קבוע — אותה קלט מפיקה אותה תוצאה.

**דוח הסבר:** לכל משבצת שנשארה ריקה מוצגת הסיבה (אף אחד לא סימן / כולם במקסימום /
חסום ע״י אילוץ זוגי / אילוץ שעות), ולכל עובד מתחת למכסה — כמה חסר וכמה סימן.

### עריכה ידנית

לחיצה על תא פותחת רשימת מועמדים, כל אחד מתויג: ★ מעדיף · ✓ זמין · ⚠ מה ייפגע אם
תשבץ אותו בכל זאת, ומספר המשמרות שלו מול המכסה. שיבוץ ידני ננעץ אוטומטית —
בנייה מחדש לא תזיז אותו.

### מסירת משמרת

אחרי שהסידור פורסם, עובד שלא יכול להגיע מוסר משמרת מהקישור האישי שלו. היא
מוצעת לשאר העובדים, והראשון שתופס מקבל אותה — הסידור והאזורים האישיים של
שניהם מתעדכנים מיד. **אין אישור מנהל.**

מה שנבדק לפני תפיסה: **תפקיד** (משמרת אחמ״ש מוצעת רק לאחמ״שים) ו**התנגשות** —
מי שכבר משובץ באותו יום לא רואה את ההצעה.

מה ש**אינו** נבדק, במכוון: מכסת המשמרות, הרשאת סגירה, שמונה שעות המנוחה
ואילוצי "לא עובדים יחד". כולם נאכפים כשהאלגוריתם בונה סידור, אבל לא במסירה —
ההנחה היא שעדיף שמישהו יגיע. חילוף שעקף אחד מהם מסומן בענבר במסך השבוע
("חילופים שדורשים מבט"), כך שהמנהל רואה אותו ויכול לתקן ידנית.

**חלון הזמן:** אפשר למסור ולתפוס עד 24 שעות לפני תחילת המשמרת. אין קרון ואין
תהליך רקע, ולכן הפקיעה נגזרת מהשעון בזמן הקריאה ואינה נשמרת: הצעה שלא נתפסה
פשוט מפסיקה להופיע, והמשמרת נשארת אצל מי שהציע אותה.

**"הראשון תופס"** נשען על שתי כתיבות מותנות ב-`src/lib/swap-board.ts`, לא על
בדיקה-ואז-כתיבה. `npm run swap:race` מוכיח את זה מול מסד אמיתי — כולל שזירה
דטרמיניסטית של שתי טרנזקציות. הסקריפט מסרב לרוץ בלי `SWAP_RACE_DB` מפורש.

### הוספה ליומן

בתחתית "המשמרות שלי" יש כפתור "הוספה ליומן", ובחלון בוחרים:

- **יומן אפל, מנוי שמתעדכן לבד** — `webcal://…/api/calendar/<token>.ics`
  (`src/lib/calendar-feed.ts`). כתובת אישית לכל עובד, בלי סשן: היומן לא שולח
  עוגיות, ולכן המפתח האקראי (`Employee.calendarToken`) הוא ההרשאה. נוצר בפעם
  הראשונה שהעובד פותח את החלון, ו"קישור חדש" מחליף אותו (הישן מחזיר 404).
  הקובץ מכיל את המשמרות מכל השבועות שפורסמו, משבועיים אחורה, בלי משמרות
  שנמסרו — מה שנעלם מהקובץ נמחק מהיומן לבד.
- **יומן גוגל** — משמרת אחרי משמרת (קישור לכל משמרת). מנוי בגוגל אפשר להוסיף
  רק מהמחשב, ולכן אותה כתובת מוצגת שם עם הוראות; גוגל מעדכן אותה פעם בכמה
  שעות.
- **הורדה חד-פעמית** (`/me/calendar`, מאומת בסשן) — משמרות השבוע כקובץ.

**בהורדה החד-פעמית** משמרת שנמסרה אחרי ההורדה תישאר ביומן. הקובץ מקטין את
זה בשתי דרכים: מזהה יציב לכל משבצת, כך שהורדה חוזרת מעדכנת במקום לשכפל,
ומשמרת שנמסרה נפלטת עם `STATUS:CANCELLED` כדי שהורדה חוזרת תסיר אותה. שתיהן
תלויות בלקוח היומן. במנוי הבעיה לא קיימת.

השעות נפלטות ב-UTC ולא בשעה מקומית עם `VTIMEZONE` — הרגע המוחלט כבר מחושב
נכון, וזה נכון אוטומטית גם בשעון קיץ. הקיפול ל-75 אוקטטים סופר **בתים**
ולא תווים, כי אות עברית היא שני בתים ב-UTF-8.

## מבנה הפריסה

| | |
|---|---|
| אפליקציה | Vercel, פונקציות ב-`fra1` (`vercel.json`) |
| מסד נתונים | Prisma Postgres, `eu-central-1` |
| חיבור | `@prisma/adapter-pg` דרך `src/lib/prisma-client.ts` |
| סודות | משתני סביבה בלוח הבקרה של Vercel |
| פריסה | אוטומטית מכל דחיפה ל-`main` |

משתני הסביבה הנדרשים: `DATABASE_URL`, `AUTH_SECRET`, `VAPID_PUBLIC_KEY`,
`VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.

`TZ` **אינו נדרש.** שכבת הזמן ב-`src/lib/time.ts` אינה נשענת על שעון התהליך —
ראה ההסבר שם — ו-`TZ=UTC npm test` הוא מה שמקבע את זה. Vercel רץ ב-UTC וזה לא
משנה דבר.

`AUTH_SECRET` חייב להישאר יציב. שינוי שלו פוסל את כל הסשנים הקיימים וכל הצוות
נזרק החוצה.

### למה עזבנו את Prisma Compute

Compute מכבה את המכולה כשאין תנועה, ויש שתי התעוררויות שונות:

| | |
|---|---|
| הקפאה — התהליך חי, המכונה קפואה | **0.3–0.7 שניות** (נמדד, 7 מתוך 7) |
| פינוי מלא — המכולה נעלמה, חבילה מאפס | **27–55 שניות** |

השנייה היא זו שנראתה למשתמש כ"האתר לא נטען". `downloading source archive` בלוג
הוא הסימן לה.

**אין ב-Prisma Compute הגדרה שמונעת את זה** — לא ב-`ComputeAppConfig`, לא ב-CLI
ולא במטא-נתונים (נבדק שוב באוגוסט 2026). מה שהיה זה קרון חיצוני שדופק כל דקה,
וזה טלאי: כל פעימה שנופלת היא 27–55 שניות למי שנכנס באותו רגע.

> **מלכודת ששווה לזכור:** היה שם גם "פינג עצמי" שאמור היה לתזמן לעצמו בקשה כל
> 30 שניות. **הוא מעולם לא עבד.** הפלטפורמה מקפיאה את התהליך, ותהליך קפוא אינו
> מריץ טיימרים — נמדד: תשע דקות שעון, `process.uptime()` עלה מ-11 ל-62 בלבד.
> `setTimeout` שם סופר זמן ריצה, לא זמן שעון.

ב-Vercel אין מכולה שנרדמת, וההתעוררות של פונקציה היא בסדר גודל של שנייה.

### מה נמחק במעבר

`prisma.compute.ts`, `scripts/prune-standalone.mjs`, `/api/ping` והמשתנה
`APP_URL` — כולם היו קיימים אך ורק בשביל Compute. גם `output: "standalone"`
ירד מ-`next.config.ts`: Vercel בונה פלט משלו.

`outputFileTracingExcludes` על sharp **נשאר**. `next/image` אינו בשימוש, אבל
Next מושך את sharp דרך מעקב הקבצים של השרת עצמו, וב-Vercel זה מתורגם לגודל
פונקציה — כלומר לזמן התעוררות.


סקריפטים שרצים ב-`tsx` (`db:seed`, `simulate`) חייבים `import "dotenv/config"` —
בניגוד ל-Next ול-`prisma.config.ts`, tsx לא טוען `.env` מעצמו.
